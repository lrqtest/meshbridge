# 缓存与交互性能

MineAI 是平台，MeshBridge 是项目。两者共用静态资源实现，但不共享浏览器
登录状态或用户数据缓存。本次不引入 Redis；先减少可验证的重复网络请求和
重复渲染，再通过实际负载决定是否需要分布式缓存。

## 静态资源

生产模式由 kit 为 HTML 中的本地 JS、CSS、图标引用追加内容版本，并注入
`asset-v`，供动态加载的字典、图标使用。当前版本资源使用
`public, max-age=31536000, immutable`。HTML、未版本化和旧版本请求仍使用
`no-cache` 与 ETag：不是禁止缓存，而是使用前必须校验。

应用资源和 kit 资源由同一个处理器服务，避免动态字典使用组合版本时仍落到
另一个版本命名空间。资源变更会改变 HTML 的版本及 ETag。不存在的资源、
API 和下载仍返回 404，Mesh 的 CSP 不变。`MESH_WEB_DIR` / `KIT_WEB_DIR`
开发模式不追加版本，不会把编辑后的 JS 长期缓存。字体保留原有长期缓存。

## 页面数据

可选共享运行时 `kit/cache.js` 提供单实例最多 64 个条目的内存 LRU 缓存，
包括在途请求；不会写入 localStorage、sessionStorage 或共享 HTTP 缓存。

| 数据 | 有效期 | 行为 |
| --- | --- | --- |
| 初始化/公开配置状态 | 20 秒 | 相同在途请求合并；设置写入后失效 |
| 健康检查 | 15 秒 | 页面进入和轮询复用同一请求 |
| 设备 | 15 秒 | 切页复用；依赖它的页面不强制重复拉取 |
| 传输 | 5 秒 | 活跃传输每 5 秒检查；空闲时每 15 秒检查 |
| 隧道、中继、项目、隧道设置 | 30 秒 | 按页面需要读取 |
| 审计首页、SMTP 配置 | 15 秒 | 仅当前用户内存；服务端权限检查不变 |

GET 接口仍使用 HTTP `no-store`。缓存仅减少相同身份、短有效期内的重复读取，
不会代替服务端认证或权限校验。成功写操作保守失效相关私有查询和审计；
配置写入另失效初始化状态。失效和账号变化会取消旧读取，迟到结果不能重新
填充缓存，也不能在异步恢复后写回控制台；旧账号的 401 不会退出新账号。

登录、退出及跨标签页 token 变化清理内存数据、分页、一次性隧道密钥和渲染
指纹，停止旧页面轮询并隐藏旧控制台。已有 `/me` 复用规则不变，仅合并
并发读取；本次没有扩大 SSO 或权限结果的服务端缓存时间。

切页立即展示已加载数据，过期后后台刷新。概览模块逐个完成、逐个更新。
数据相同时保留表格节点；语言、筛选、依赖数据和相对时间变化仍触发渲染。
隐藏页面、弹窗期间暂停轮询；旧页面请求不能重启新页面的轮询。自动轮询
遵守每种数据的 TTL，手动刷新绕过 TTL，但仍合并在途请求。

首次请求失败展示可重试错误，不能冒充空列表；后台请求失败保留旧数据。
审计翻页并发不会追加两遍，首页没有变化时保留展开的后续页。

## 验证

在 MeshBridge 目录运行 `make test vet i18n-check runtime-check build`。
共享改动另运行根目录 `bash scripts/check-platform.sh`；该命令不部署。
对独立本地服务还可运行 `node scripts/cache_http_test.cjs http://127.0.0.1:18761/`
验证实际 HTTP 响应；此脚本只读取静态资源，不登录、不写入、不生成并发负载。

自动化覆盖 TTL 边界、强制读取、在途合并、失败重试、写后失效、LRU 上限、
账号变化、迟到结果、微任务边界、旧 401、无变化 DOM、缓存先展示、初次错误、
审计分页及概览分块更新。Go 测试验证 HTML/资源版本、旧版本回退、ETag/304、
开发模式更新、真实 404 和精确保留 CSP。

## 生产性能验收与 Redis 的引入条件

功能回归不是生产提速比例。上线后在相同浏览器、网络、账号和数据规模下记录：

1. 冷访问与热访问的请求数、传输字节、资源网络校验数及页面可操作时间。
2. 控制台首次进入、设备/传输来回切页：已加载内容是否立即显示、TTL 内是否
   复用请求；强制刷新和写后刷新是否看到最新内容。
3. 单用户及受控并发下 API 的 p50/p95、数据库查询耗时、轮询请求数量和
   浏览器渲染耗时。禁止未经批准直接对生产做压力测试。
4. 网络失败、慢请求、账号切换、多标签页退出，以及新版本发布后的资源更新。

如果测量表明重复聚合/查询占主要延迟，或多个实例需要共享缓存，再引入
Redis cache-aside：按应用/用户/权限分区、短 TTL、写后失效、请求合并、
命中率与延迟监控、Redis 故障时受控回源。Redis 不可成为身份校验的绕过路径，
也不应缓存登录响应、验证码、授权码、一次性隧道密钥或 SMTP 密码。
